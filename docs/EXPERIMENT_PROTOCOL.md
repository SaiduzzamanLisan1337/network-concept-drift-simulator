# Experiment Protocol

This document records the default protocol so results can be interpreted and reproduced.

## Research question

How do abrupt and gradual changes in network-flow feature distributions, class-conditional structure, and attack prevalence affect a frozen binary IDS classifier compared with the same classifier updated incrementally from labelled windows?

## Synthetic data definition

Each row is generated by first sampling a binary label from the phase's target attack prevalence, then sampling eight latent Gaussian coordinates around a class-conditional centre. The observed network-flow features are monotonic exponential or logistic transforms of those coordinates. A shared phase-specific offset changes feature distributions, while the vector separating benign and attack centres controls the class-conditional relationship. This is a deliberately simplified synthetic generator, not a calibrated model of a specific network.

| Feature | Interpretation | Transform family |
|---|---|---|
| `flow_duration_ms` | Flow duration in milliseconds | Exponential transform |
| `src_bytes` | Source-to-destination byte count proxy | Exponential transform |
| `dst_bytes` | Destination-to-source byte count proxy | Exponential transform |
| `packet_count` | Packet-count proxy | Exponential transform |
| `syn_ratio` | SYN-related ratio proxy in [0, 1] | Logistic transform |
| `dst_port_diversity` | Destination-port diversity proxy | Exponential transform |
| `failed_connection_ratio` | Failed-connection ratio proxy in [0, 1] | Logistic transform |
| `inter_arrival_ms` | Inter-arrival time proxy in milliseconds | Exponential transform |

Values are generated to be plausible-looking numerical flow features, but they are not tied to packet-level network semantics or measured protocol constraints. Do not represent them as real captures.

## Default phase schedule

The stream is split into five equal-duration phases. The first four changes are step changes at boundaries; the last phase interpolates parameters sample-by-sample.

1. **Stable:** target attack prevalence 0.18, baseline class separation, no shared feature offset.
2. **Covariate shift:** target prevalence remains 0.18 and class separation remains unchanged, but a shared feature offset changes.
3. **Concept drift:** target prevalence remains 0.18 and the feature offset remains, but the benign/attack separation vector changes.
4. **Class-prior shift:** the changed concept persists and target attack prevalence rises to 0.42.
5. **Gradual transition:** the feature offset and class separation interpolate toward a new near-baseline state; target attack prevalence moves from 0.42 toward 0.18.

The observed prevalence fluctuates around the target due to Bernoulli sampling. Use `event_index` to preserve stream order; `timestamp` is only a synthetic event clock.

## Training and evaluation

- The baseline training sample is independently generated from the stable distribution.
- A `StandardScaler` is fitted on the baseline training features and held fixed for both models.
- The baseline classifier is an `SGDClassifier` with logistic loss and a fixed random seed.
- The adaptive model starts as a deep copy of the fitted baseline classifier.
- Each stream window is scored before its labels are provided to the adaptive learner. The adaptive classifier then receives one `partial_fit` update on that labelled window.
- The frozen classifier receives no stream updates.
- All reported performance values are calculated on the current window before any update from that window.

This is a labelled, batch-online comparison. It does not model label delays, analyst verification, label noise, drift-detector latency, replay memory, or adaptation-trigger decisions.

## Outcomes

Primary metrics: attack recall, macro F1, balanced accuracy, and PR-AUC (average precision). Accuracy and attack precision are supplementary. Monitoring outcomes include average/per-feature PSI, mean standardized feature shift, and attack rate.

PSI is computed against baseline training features with quantile bins fixed by the reference data. It is descriptive and sensitive to binning; no universal PSI cutoff is treated as proof of drift.

## Reproducibility checklist

1. Record the code commit and Python/package versions.
2. Preserve `experiment_config.json` and `run_metadata.json` with each run.
3. Repeat multiple random seeds before making general claims.
4. If comparing adaptation methods, keep the stream, initial training data, preprocessing, scoring windows, and label-availability protocol identical.
5. For real datasets, document provenance, intended-use licence, feature extraction, label mapping, duplicates, preprocessing, and leakage prevention.
6. Report uncertainty and avoid claiming field performance from synthetic-only experiments.
